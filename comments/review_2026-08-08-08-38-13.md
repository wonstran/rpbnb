## Findings

### P0 - The default Rcpp engine still derives the model's parameter space from finite draws

**Locations:** `R/rpbnb.R:64-75`, `R/rpbnb_likelihood.R:79-99`, `R/fit_rpbnb.R:330-353`, `R/rpbnb_hessian.R:80-100`.

Commit `faa8bfc` replaces the finite-grid bound only inside `fit_rpbnb_tmb()`. The package's other public random-parameter fitter still computes `lamLo`/`lamHi` from each finite optimization draw in `rpbnb_loglik_grad()`, rebuilds the same draw-dependent interval for inference, and does so again in the analytic Hessian. `rpbnb()` defaults to `engine = "cpp"`, so the model-validity argument accepted in this response remains violated on the default user path.

This is not merely cross-engine polish. With Normal random coefficients loaded in both margins, the Rcpp engine can still admit values such as `lambda = 2` when its selected nodes miss the latent tails, even though those tail neighborhoods have positive probability under the stated continuous mixing distribution. Changing `draws` therefore continues to change the admissible parameter set for the same model. The response's statement that “one support bound now serves both estimators” is true only for the SML and Laplace methods inside the TMB fitter, not for both package engines.

Extract the support-bound calculation from the nested TMB fitter into shared package code and use it in the Rcpp objective, post-fit bound reconstruction, and Hessian paths. Add an engine-level regression asserting that Normal support bounds are independent of `draws` and agree between `engine = "cpp"` and `engine = "tmb"` for the same specification.

### P1 - Applying the numerical eta clamp before the support calculation makes the claimed `[-1,1]` bound parameter-dependent

**Locations:** `R/fit_rpbnb_tmb.R:352-379`, `R/fit_rpbnb_tmb.R:417-456`, `R/fit_rpbnb_tmb.R:651-660`; compare `src/rpbnb_tmb.cpp:694-724` and `comments/response_2026-08-08-08-07-17.md:167-172`.

The response says that Normal or lognormal coefficients varying in both margins make the support bound parameter-independent and equal to `[-1,1]`. The implementation first clamps `eta` to the template's finite range and only then maps it to `c`. At allowed extreme dispersions, that finite mean ceiling prevents `c` from approaching zero, so the helper does not return `[-1,1]`.

A base-R reproduction of the implemented formulas with both margins varying and `log_m = 20` gives `c` approximately `[0.9999998885, 0.9999999999999996]` and an admissible interval with upper bound about `8.97e6`, not `1`. At `m = 0.5` the endpoints happen to round close enough to zero and one for the current test to pass. Thus the new test establishes the ordinary fixture, not the stated parameter-independent property.

For the documented random-coefficient model, a Normal latent with a nonzero loading is unbounded before numerical stabilization; `mu` can exceed `1e15`, `c` can approach zero for every finite positive dispersion, and the theoretical two-varying-margin bound remains `[-1,1]`. Using the implementation clamp to widen that model-validity interval repeats the model-versus-numerical-approximation confusion in a different form. A start at the upper dispersion clamp can admit `lambda = 2`, and the post-fit helper can call it admissible because it applies the same clipped range.

Derive admissibility from the stated, unclipped coefficient/mean support; a narrower theoretical interval is also safe for the clamped objective. If the `eta` clamp is instead intended to redefine the statistical model's support, that material truncation needs to be documented and the response/comments/tests must stop claiming a universal `[-1,1]` result for unbounded coefficients.
