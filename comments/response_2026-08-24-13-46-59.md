# Response: TMB SML large-draw OOM plan review

Responding to `comments/review_2026-08-24-13-37-07.md`. All seven findings are accepted; the plan file (`read-docs-tmb-sml-large-draws-oom-guide-compiled-abelson.md`) has been revised as described below. No code has been changed yet.

## [P1] Pass the requested parameter vector explicitly to `obj$report()`

**Accepted.** Confirmed against TMB's `MakeADFun` source: `report <- function(par = last.par)`, and `last.par` is only advanced by calls into the raw objective, which the wrapper's pass 1 deliberately avoids. The plan now requires `obj$report(par)` with the explicit parameter vector on every chunk evaluation, and adds the suggested regression test: seed `obj$env$last.par` with a deliberately different vector before calling the wrapper's `fn`/`gr` and assert the results are unaffected. The same explicit-argument rule is extended to any other raw-object call the wrapper makes (`gr(par)` was already explicit).

## [P1] `ceiling(weighted_workload / max_workload)` does not always produce a safe integer chunk size

**Accepted.** The counterexample is correct — deriving `C` from the continuous ratio and then re-deriving the chunk size by integer rounding can land the realized chunk back over budget. The resolver is redesigned to work in draws-per-tape space:

1. Compute `one_draw_workload = n * family_weight * tape_multiplier`; hard-stop if it already exceeds `max_workload` (unchanged honest-refusal case).
2. `draws_per_chunk_max = floor(max_workload / one_draw_workload)`.
3. Choose the layout directly from `draws_per_chunk_max` (see the next-but-one finding for the layout itself), then **re-check the realized per-chunk workload after all rounding** and assert it is within budget before proceeding.

Tests will cover fractional budgets just below integer boundaries (the review's `draws = 10`, budget `3.9` case) and `parallel_tape = TRUE` (where `tape_multiplier` scales the one-draw workload).

## [P1] Boundary refits will discard chunking and can recreate the original OOM

**Accepted — this was a real hole.** Verified: `rpbnb_tmb_boundary_tests()` builds `rpbnb_tmb_control(..., max_workload = Inf)` when no control is supplied (`R/tmb_boundary_tests.R:203-215`), and `rpbnb()` calls it without forwarding the main fit's control (`R/rpbnb.R:400-403`), so every restricted refit of an auto-chunked fit would run as one full tape. The plan now adds:

- A persisted `fit$integration` (name TBD at implementation) recording `draws_requested`, `draws_effective`, the resolved chunk layout, `max_workload` actually used, and the thread/`parallel_tape` policy.
- `rpbnb_tmb_boundary_tests()` reconstructs its default control from that record instead of `max_workload = Inf`, and re-resolves a safe chunk layout whenever `boundary_draws` differs from the original draw count (never blindly reusing the old layout or `Inf`). The Laplace-to-SML fallback refit path gets the same treatment.
- Tests: an end-to-end `rpbnb(..., boundary_tests = TRUE)` case and a direct `rpbnb_tmb_boundary_tests()` case, both asserting the refit resolves a chunked layout when the workload demands one.

## [P2] Rounding draws up changes the SML estimator

**Accepted; the rounding is dropped entirely.** The requested draw set is preserved exactly. Instead of forcing equal chunks via `C * ceiling(R / C)` extra Halton points, the layout allows at most two chunk sizes (an even split with sizes differing by at most one). Since `DATA_UPDATE` cannot change dimensions, the remainder size gets its own small `MakeADFun` object alongside the main chunk-sized one — at most two tapes, both counted against the workload budget by the resolver. The per-observation combination becomes draw-count-weighted:

`log S_i = logsumexp_c( log S_ic + log Rc_c ) − log R`, with gradient weights `w_ic = Rc_c · S_ic / Σ_c Rc_c · S_ic`,

which is exact for the user's requested `R` draws — the "exactness" claim now genuinely covers the user-facing contract, and there is no `draws_effective ≠ draws_requested` divergence in the default path (the metadata fields are still stored, and equal by construction here; they exist for the boundary-refit record above). `tape_chunks > draws` is validated and rejected with a clear error rather than silently inflating the draw count.

## [P2] Define the complete `fit$obj` compatibility contract for the wrapper

**Accepted.** The plan now specifies the wrapper as a `MakeADFun`-shaped list with an explicit contract:

- `par`: forwarded from the raw object (fixed-effect vector, same names/order).
- `fn(par)` / `gr(par)`: full-draw chunked implementations (the documented supported operations).
- `he(par)`: deterministic error stating that the chunked objective has no taped Hessian and pointing at the finite-difference path the package itself uses.
- `report(par)`: forwards to the raw object after restoring chunk-1 `Z1`/`Z2` and `w = 1`, documented as per-chunk (chunk 1) semantics.
- `env`: forwarded (needed by existing code paths), with the guarantee that `Z1`, `Z2`, and `w` are restored to chunk 1 / all-ones on **every** exit path of `fn`/`gr` (including error paths, via `on.exit`), so a `saveRDS()`/`readRDS()` round trip retapes into a deterministic state rather than whichever chunk ran last.
- A class attribute marks it for the profile-CI guard and any future TMB-only operation checks.

Tests added: `keep = "full"` retention, post-fit `fn`/`gr` evaluation at a non-optimal parameter vector, `he()` error message, and an RDS round trip exercising the retape.

## [P2] Benchmark the report pass before promising "~2x" cost

**Accepted.** The point about `REPORT()` running only in ordinary double-mode execution (outside the parallel regions) is well taken — at `n_cores > 1` the serial report pass is not amortized the way the parallel gradient sweeps are. All numeric cost multipliers are removed from the plan's user-facing message text; the auto-chunk `message()` describes the cost qualitatively ("slower gradient evaluations") until the Phase 3 benchmark measures wall time at one thread and at representative multi-thread settings per family. The Phase 2 spike is upgraded from "verify a vector is returned" to verifying report **values** against a hand computation and verifying behavior under compiled-in OpenMP threading.

## [P3] Standardize on `inst/tmb_benchmark_memory.R`

**Accepted.** The short name `inst/benchmark_memory.R` in the plan was an error — only `inst/tmb_benchmark_memory.R` exists. The plan now uses the real path everywhere, and Phase 3 gains an explicit sub-task: while refreshing `TAPE_CALIBRATION$source`, the CSV, README, and drift tests, repair the existing stale `inst/benchmark_memory.R` self-references in the benchmark script and code comments so only one name survives.

## [P3] Complete the distribution and failure-path test matrix

**Accepted.** The test plan now includes: triangular coefficients in at least one chunk-equivalence case (all four registered distributions covered); an error injected during a middle chunk asserting `Z`/`w` restoration; non-finite chunk log-likelihoods/weights; `tape_chunks = 1` (must be byte-identical to the unwrapped path); `tape_chunks > draws` (clear rejection, per the rounding finding); no-random-coefficient SML (effective draws forced to 1 — resolver must short-circuit, never chunk); and assertions on the requested/effective draw metadata and persisted integration record.

## Acceptance criteria

All six suggested acceptance criteria are adopted verbatim into the plan's Verification section, including the stale-`last.par` condition in criterion 1, slope-based (not absolute quarter-peak) memory verification in criterion 5, and measurement-based runtime messaging in criterion 6.
