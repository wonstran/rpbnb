## Detail

### P1 — no-`newdata` lognormal prediction

`predict.rpbnb_fit(object)` returned the cached `object$mu1/mu2` (the capped
finite-draw means computed in the fitter), which never saw the analytic-infinity
rule, while `predict(object, newdata = training)` recomputed and returned `Inf`
on `sign·x > 0` rows. The two disagreed although both advertised the same
`estimand`. The no-`newdata` path now recomputes from the stored design via
`.rp_predict_mu()` (cached means are used only when no draws are stored, e.g. a
legacy fit), so the estimand — including `Inf` — is identical either way. New
tests assert `predict(fit)` equals `predict(fit, newdata = training)` for
positive- and negative-sign lognormal coefficients on both the Famoye and copula
paths, and that `Inf` lands exactly on the `sign·covariate > 0` rows.

### P2 — scalar scale

`parse_rand_spec()` assigned a possibly length->1 `scale`/`sd` into a single
vector slot, so `sd = c(0.2, 0.3)` was truncated to `0.2` with an R
replacement-length warning rather than rejected. It now errors at parse time
unless each scale is a single numeric value; `chk_rand_spec()` continues to
enforce finite and strictly positive. Tested with length-two and length-zero
scales.

### P2 — prediction coverage

The prior response claimed the full distribution-by-dependence matrix; the
committed tests did not cover negative-sign lognormal or lognormal-on-copula
prediction. Both are now added, plus the `newdata = NULL` consistency checks.
The coverage sentence in `comments/response_2026-07-15-23-07-35.md` has been
corrected to list exactly what is tested and to state plainly that
normal/uniform/triangular prediction on the copula path is not separately
exercised.

### P2 — AGENTS.md

Gotcha #4 previously told maintainers that RP standard errors use a separate
smaller `seed + 1` Halton set and to raise `draws_hessian` for stability — the
exact behavior `e9d82b5` removed. It now states the same-draw curvature policy,
that `draws_hessian` is a backward-compatible no-op, and that non-positive-
definite repair is recorded on `fit$hessian_diag`.
