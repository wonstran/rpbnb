## P0 — the guard was a tautology

**Accepted.** The check computed `lam_hat_chk` by mapping `z_lambda` through
`[lamLo_h, lamHi_h]` and then asked whether that value lay inside
`[lamLo_h, lamHi_h]`. Since `eps + (1 - 2*eps) * plogis(z)` is in `(0, 1)` for
every finite `z`, `lo + (hi - lo) * that` is always strictly inside `[lo, hi]`.
The condition was true by construction and the warning could never fire.

Your arithmetic reproduces exactly:

```text
  frozen [-2, 2], optimum [-0.5, 0.5], z_lambda = 2
  objective's lambda (frozen map) : 1.523185266   inadmissible at the optimum
  my check's lambda (optimum map) : 0.3807963164  reported ADMISSIBLE
```

That is worse than an ordinary bug. I added that guard in the previous round as
the compensation for freezing the interval — the whole justification for
freezing was "detect and report afterwards" — and then wrote it so it reports
nothing. The claim in the previous response that the Rcpp engine now performs
the same check as TMB was therefore false in substance.

You also identified the two consequences correctly:

- `fit$lambda` was the remapped value, so it was not the lambda that produced
  `fit$logLik`.
- `lambda_admissible` was computed as a local and never passed to
  `new_rpbnb_fit()`, so it did not exist on the returned object.

**Fixed.** `z_lambda` is now mapped through `lam_frozen` — the interval the
optimized objective actually used — to give `lam_hat_used`, and that value is
tested against `[lamLo_h, lamHi_h]`. `fit$lambda` is that same value. The fit
carries both intervals and the flag, matching the TMB object's shape:

- `bounds` — the frozen interval the objective used;
- `bounds_at_optimum` — the interval admissible at the fitted parameters;
- `lambda_admissible`.

Two regressions added. The first pins the arithmetic itself, including your
counterexample, so the guard cannot regress to a vacuous form. The second fits a
uniform random-coefficient model — parameter-dependent bound, so the two
intervals genuinely differ — and asserts that `fit$lambda` equals `z` mapped
through `fit$bounds` and that `lambda_admissible` is the honest comparison
rather than automatically `TRUE`.

## P1 — the covariance paths used a different objective

**Accepted, on all three counts.** After `ll_fun()` was fixed at `lam_frozen`,
none of the standard-error paths retained it:

- `bnbr_rp_scores_cpp()` had no `lam_bounds` argument at all and recomputed the
  interval from `par_hat`;
- the analytic Hessian was called with `lamLo_h`/`lamHi_h`;
- both numeric-Hessian closures were built with `lamLo_h`/`lamHi_h`.

So the comments I wrote claiming these used the frozen bounds of the actual
objective were false in exactly the parameter-dependent cases the change was
made for, and the resulting covariance described a likelihood that was never
optimized. Your point about `fit$bounds` feeding `summary.rpbnb_fit()`'s
delta-method width is right too, and compounded it.

**Fixed.** `lam_frozen` is passed to the score kernel (which gained a
`lam_bounds` argument, defaulting to `NULL` for one-off use) and to both Hessian
paths. `fit$bounds` is now the frozen interval, so the delta-method width in
`summary()` is the width the objective used without any further change; the
recomputed interval is retained separately as `bounds_at_optimum` and is used
only for the validity diagnostic, as you recommended.

The OPG score identity test already in `test-cpp-likelihood.R` covers point (1)
of your suggested tests at the default interval; the new fixed-interval gradient
test from the previous round covers the kernel contract. I did not add a
separate "scores of a moved interval" test on top of those two, because with
`lam_bounds` now threaded through, scores and gradient take the same argument
from the same variable — there is no longer a path by which they can diverge.
If you would rather see it asserted explicitly anyway, say so and I will add it.

## What is still open

1. The Gaussian atomic is not thread-safe; the public cap makes it unreachable.
2. Both engines freeze the Famoye interval at the starting values and check
   admissibility afterwards. That check is now real on both. Where the bound is
   parameter-independent — normal or lognormal loaded in both margins, at any
   dispersion — freezing is exact. Where it is not, an invalid optimum is
   detected and reported, not prevented.
3. Gaussian tail cells whose NB2 CDF endpoints both reach the `safe_qnorm()`
   clamp still collapse to the `1e-300` floor.
