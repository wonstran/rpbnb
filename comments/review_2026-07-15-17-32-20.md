# rpbnb project and model review

**Reviewed:** 2026-07-15 17:32:20 America/New_York  
**Target:** `master` at `1f969ac`, including the current modified/untracked working tree  
**Scope:** fixed-parameter BNB, Famoye/Sarmanov and discrete-copula dependence, RP-BNB maximum simulated likelihood, simulation, prediction, inference, diagnostics, C++ parity, tests, and package health.

## Executive assessment

The project has a strong research-code core: model preparation is careful, likelihood code is separated by concern, analytic gradients and Hessians have numerical-oracle tests, and the R/C++ implementations are explicitly checked for parity. The independence BNB path is a useful baseline, and the fixed-parameter copula BNB path is the most convincing dependent model in the current package.

The package as a whole is not yet production-ready. The highest-priority problem is a mathematically incomplete lower bound for negative Famoye/Sarmanov dependence. That bound is shared by fixed BNB, RP-BNB, simulation, Hessians, and the C++ core, so negative-lambda fits can represent a joint PMF that becomes negative in the count tails. RP prediction and natural-scale reporting also do not honor the supported non-normal random-coefficient distributions. Several inference and validation paths return plausible-looking output when they should warn or error.

| Model path | Assessment | Recommended status |
|---|---|---|
| `fit_bnb(..., dependence = "independence")` | Straightforward two-margin NB2 baseline; API and standard methods are coherent. | Usable, subject to normal `glm.nb` limitations. |
| `fit_bnb(..., dependence = "famoye")` | Good analytic implementation and tests, but the negative-dependence parameter region is not valid over the full support. | Do not use for negative dependence until P0 is fixed. Revalidate positive-dependence fits after the shared bound change. |
| `fit_bnb(..., dependence = copula(...))` | Strong gradient/PMF tests and reasonable parameter transforms. Diagnostics and Hessian failure handling need work. | Promising beta/research use. |
| `fit_rpbnb(..., dependence = "famoye")` | Sophisticated MSL implementation with randomized Halton draws, analytic/OPG options, and R/C++ parity. Inherits the P0 bound defect; prediction and default inference need hardening. | Experimental/research use only. |
| `fit_rpbnb(..., dependence = copula(...))` | Numerically ambitious and well tested at the likelihood level, but very slow, incompletely predictive, and weakly guarded at the API boundary. | Experimental. |

## Prioritized findings

### P0 - The Famoye/Sarmanov lower lambda bound does not guarantee a non-negative PMF

**Locations:** `R/famoye_core.R:21-27`, `src/halton_parallel.cpp:140-168`; consumed throughout `R/bnb_likelihood.R`, `R/rpbnb_likelihood.R`, `R/rpbnb_hessian.R`, `R/fit_rpbnb.R`, and `R/simulate_bnb.R`.

The model uses

```text
h_t(y) = exp(-y) - c_t
P(y1,y2) = p1(y1) p2(y2) [1 + lambda h_1(y1) h_2(y2)].
```

For non-negative counts, `h_t(0) = 1 - c_t` and `h_t(y)` tends to `-c_t` in the upper tail. The largest positive value of `h_1 h_2` is therefore

```text
max((1 - c1)(1 - c2), c1*c2),
```

so the valid per-observation lower bound is

```text
-1 / max((1 - c1)(1 - c2), c1*c2).
```

The implementation uses only `-1 / ((1 - c1)(1 - c2))`. This is too permissive whenever `c1*c2` is the larger positive corner, which commonly occurs at low means. The package's local copy of Famoye (2010), `docs/papers/On the bivariate negative binomial regression model.pdf`, confirms the multiplicative PMF being implemented; the support argument above follows directly from that PMF.

Reproduction with `mu1 = mu2 = 0.1` and `m1 = m2 = 0.5`:

```text
c = 0.939663
implemented lower bound = -274.686085
valid lower bound       =   -1.132545
tail dependence factor at implemented bound = -241.538772
```

The likelihood's `pmax(dep, 1e-300)` can conceal an invalid observed factor by flooring it, but it cannot make the underlying joint distribution valid. The approximate simulator similarly applies `pmax(P2 * W, 0)` and renormalizes, which changes the requested model when weights are negative.

**Recommendation:** fix the bound in the R helper and the independent C++ implementation, add tests covering `c > 0.5`, verify non-negativity over a large count grid for both lambda endpoints, and repeat parameter-recovery benchmarks. Treat existing negative-lambda estimates and simulations as unvalidated.

### P1 - RP prediction and natural-scale reporting ignore non-normal random distributions

**Locations:** `R/methods.R:15-40`, `R/methods.R:78-112`, `R/methods.R:298-310`, `R/fit_rpbnb.R:9-24`, `R/fit_rpbnb.R:388-396`, `R/fit_rpbnb_copula.R:122-131`.

Fitting supports normal, uniform, triangular, and sign-constrained lognormal random coefficients, but `.bnb_predict_mu()` only recognizes parameter names beginning with `log_sd`. It applies the normal correction `0.5 * sd^2 * x^2` and ignores `log_w` and `log_s` parameters. The fitted object does not retain `dist1`, `dist2`, `sign1`, or `sign2`, so correct distribution-specific prediction cannot be reconstructed later.

Confirmed uniform example at `x = 2`:

```text
package predict()       = 1.90854637
exact uniform mean      = 2.46322168
package / exact         = 0.774817
```

The same fitted model's natural-scale summary omitted its `log_w1:x` scale entirely; it listed only `m1`, `m2`, and lambda. Lognormal scales are likewise omitted. For a positive lognormal random coefficient and positive covariate, the population mean `E[exp(x*beta)]` may be infinite even though a finite set of simulation draws produces a finite draw average; that distinction must be explicit.

**Recommendation:** store normalized random specifications and prediction draws/settings on the fit object. Implement distribution-aware prediction (analytic where valid, controlled simulation otherwise), label the estimand as conditional or integrated, and add tests for every supported distribution on both Famoye and copula fits.

### P1 - Natural-scale Wald p-values for dispersion and random scales are not valid tests of zero

**Locations:** `R/methods.R:82-105`, `R/methods.R:108-149`.

The summary computes `z = estimate / delta-method SE` after transforming `log_m`, `log_sd`, `log_w`, or `log_s` with `exp()`. For a positive parameter `a = exp(eta)`, this ratio is `1 / SE(eta)`; it is not a Wald test of `a = 0`, because zero corresponds to `eta = -Inf`, outside the regular interior parameterization. The raw log-scale table is not a zero-variance test either: testing `log_sd = 0` tests `sd = 1`.

This can attach significance stars to variance and dispersion components without a valid null distribution. Boundary tests generally require an appropriate likelihood-ratio mixture, score test, or bootstrap.

**Recommendation:** remove p-values/stars for positive scale components unless a defensible hypothesis is stated. Report estimates and intervals, and provide an explicit boundary-aware test when needed. Lambda, Gaussian rho, and Frank theta can have regular zero-dependence tests when zero is interior; Clayton independence is a boundary case.

### P1 - Simulator and dependence inputs are insufficiently validated

**Locations:** `R/copula.R:23-25`, `R/simulate_rpbnb_copula.R:38-84`, `R/fit_rpbnb.R:86-101`.

Confirmed behaviors:

- `copula("normal", par = 1.2)` is accepted; simulation returns NA counts because `sqrt(1 - rho^2)` is invalid.
- `copula("kimeldorf", par = -1)` is accepted; the sampler takes its near-independence branch, while the recorded Kendall tau becomes `NaN` through `log(-1)`.
- `simulate_rpbnb_copula(random_1 = "x1", ...)` accepts a character random spec with no scale and returns NA `mu1` and `y1` instead of an informative error.
- `simulate_rpbnb_copula()` does not mirror `simulate_rpbnb()`'s checks for named positive dispersions, valid random names, and non-missing scales.
- `fit_rpbnb(dependence = "typo", ...)` silently fits the Famoye path because non-copula strings are never passed through `match.arg()`.

**Recommendation:** validate native copula domains in `copula()` whenever `par` is supplied (`|rho| < 1`, Clayton `theta > 0`, finite Frank theta); centralize simulator validation; reject missing/non-positive scales and dispersions; and make `fit_rpbnb()` accept only `"famoye"` or an `rpbnb_copula` object.

### P1 - Copula BNB goodness-of-fit cannot fit its advertised null model

**Locations:** `R/diagnostics.R:32-88`.

`bnb_gof()` claims to refit the intercept-only model with the same dependence structure, but passes `fit$dependence` back to `fit_bnb()`. A copula fit stores `fit$dependence` as a string such as `"normal"`; `fit_bnb()` accepts only `"independence"`, `"famoye"`, or a `copula()` object. A confirmed Gaussian-copula call warned and returned all pseudo-R-squared values as NA:

```text
Null model could not be fitted ('arg' should be one of "independence", "famoye")
```

In addition, all pseudo-R-squared measures are forcibly clamped to `[0, 1]`. Negative adjusted McFadden or other values can be diagnostically meaningful (for example, a penalized full model performing worse than the null); clamping hides that information.

**Recommendation:** reconstruct `copula(fit$cop_family)` for copula null fits, assert null-fit convergence, and return raw pseudo-R-squared values with an explanation rather than silently clipping them.

### P1 - Hessian repair can turn non-identification or a saddle point into apparently valid inference

**Locations:** `R/fit_bnb.R:81-114`, `R/fit_rpbnb.R:264-281`, `R/fit_rpbnb.R:319-341`, `R/fit_rpbnb_copula.R:99-108`, `R/halton_parallel.R:114-127`.

Several paths add a ridge whenever the observed information is not positive definite, or use `MASS::ginv()`, then report finite SEs and p-values without recording that repair on the fit object. A non-positive-definite Hessian may indicate a boundary, weak identification, a saddle point, or failure of numerical differentiation; silently changing it is not equivalent to observed-information inference. The copula numeric path does not even perform the eigenvalue check used in the other paths before inversion.

**Recommendation:** store Hessian eigenvalues, condition number, inversion method, ridge magnitude, score norm, and simulation settings. Warn prominently or return NA inference when curvature is invalid. Offer regularized covariance only as an explicitly requested diagnostic, not the silent default.

### P2 - Default RP numeric SEs are not the curvature of the optimized simulated likelihood

**Locations:** `R/fit_rpbnb.R:284-341`, `R/control.R:18-30`.

The default `se_method = "numeric"` regenerates a smaller Halton set with `seed + 1` and then evaluates a frozen-bound Hessian at the optimum obtained from different optimization draws. This is faster, but it is not the Hessian of the objective that produced the estimate, and the optimum need not be stationary for the Hessian draw set. With only 100 default Hessian draws, simulation noise can dominate variance-component curvature.

The analytic and OPG Famoye options use the optimization draws and are internally more coherent, although OPG has the documented boundary limitation. Copula numeric SEs do use the optimization draws.

**Recommendation:** make same-draw curvature the default, or label the current result as an approximate resimulated Hessian and expose sensitivity checks over draw counts/seeds. Do not compare MSL AIC/BIC values produced with materially different draw rules without warning about simulation error.

### P2 - Optimizer control and starting values are inconsistent with the public API

**Locations:** `R/control.R:1-84`, `R/fit_bnb.R:31-61`, `R/fit_rpbnb.R:108-217`, `R/fit_rpbnb_copula.R:51-80`.

`rpbnb_control(method = ...)` validates `NR`, `BHHH`, and `NM`, and tests assert that the selected value is stored, but all dependent fitters hard-code BFGS. The documentation partly admits this, yet exposing ignored choices remains misleading. Famoye and RP fits also start regression coefficients at zero by default, while the fixed copula fitter sensibly initializes from marginal `glm.nb` models.

**Recommendation:** either implement only compatible methods and pass the selection through, or remove unsupported values. Use marginal NB starts for all paths, allow named partial starts, and validate start length/names/finite values before optimization.

### P2 - Documentation, metadata, and source-package hygiene have drifted

The current code contains Rcpp/OpenMP and fixed/RP copula implementations, but README scope still describes these as future work. `DESCRIPTION` is version 0.1.0 while `NEWS.md` begins with 0.2.0 development. `AGENTS.md` says there is no compiled code and lists fewer source files/tests than the current project. These discrepancies make review, release, and user expectations unreliable.

The no-vignette package check reported:

- one actionable warning: undeclared `pkgload` use in `tests/bnb_rwm1984.R`;
- one code note: unqualified `integrate()` in `R/copula_core.R:205` (use `stats::integrate` or a roxygen import);
- package-structure notes for `.superpowers` and numerous top-level scripts/results not excluded by `.Rbuildignore`;
- environmental notes for unavailable CRAN/Bioconductor indexes and unverifiable clock time.

The first build attempt also could not rebuild the R Markdown vignette because Pandoc was absent from the local R toolchain. That is an environment limitation, but release CI should ensure Pandoc is available.

**Recommendation:** reconcile README/NEWS/DESCRIPTION/AGENTS metadata, tighten `.Rbuildignore`, declare `pkgload` in `Suggests` or move the script out of `tests`, qualify `stats::integrate`, and add a clean source-tarball check in CI.

## What is working well

- `.prepare_bnb_data()` aligns complete cases across both formulas and validates finite, non-negative integer responses; this avoids a subtle but serious bivariate row-pairing bug.
- NB2 parameterization is consistent (`variance = mu + m*mu^2`, `size = 1/m`), and `c_val()` is tested against a direct truncated expectation.
- Fixed Famoye analytic gradients/Hessians, RP analytic gradients/Hessians, copula gradients, and copula PMF normalization all have numerical-oracle tests.
- The R and OpenMP C++ RP likelihoods are tested for value, gradient, score, and fixed-bound parity across random-coefficient configurations.
- Randomized Halton draws are reused during optimization, giving a smooth deterministic objective conditional on seed; reproducibility tests are present.
- Data simulation preserves caller RNG behavior when `seed = NULL` and checks coefficient/design ordering.
- S3 `coef`, `vcov`, `logLik`, `AIC`, `BIC`, `predict`, `print`, and `summary` interfaces are broadly consistent, including NA-shaped covariance matrices when SEs are skipped.
- The test suite covers real-data fits, parameter recovery, degeneracy/underflow paths, multiple copula families, and four random-coefficient distributions.

## Recommended remediation order

1. Correct the shared Sarmanov lower bound in R and C++, add full-support non-negativity tests, and rerun all negative-dependence simulations/recovery studies.
2. Store random-distribution metadata in `rpbnb_fit`; fix distribution-aware prediction and summaries.
3. Remove invalid scale/dispersion significance tests and make Hessian/OPG diagnostics explicit.
4. Centralize input validation for copula parameters, dispersions, random specifications, draws, starts, and dependence dispatch.
5. Repair copula `bnb_gof()` and stop clamping pseudo-R-squared values.
6. Decide and document a coherent RP standard-error policy using the same objective/draws by default.
7. Split tests into fast unit, slow recovery, and benchmark tiers; set silent optimizer controls inside tests.
8. Clean release metadata, imports, dependencies, `.Rbuildignore`, and CI/Pandoc setup.

## Bottom line

The numerical implementation effort is substantial and several components are stronger than typical early-stage research software. However, the shared negative-lambda bound is a model-validity blocker, and current RP prediction/inference can be misleading outside the normal-random-coefficient case. Resolve those before treating BNB/RP-BNB output as production statistical inference; until then, use the package as experimental research software with the fixed independence and fixed copula paths receiving the most confidence.
