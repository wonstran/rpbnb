## Findings

### P0 - Finite SML draws are not the support of the random-coefficient model

**Locations:** `R/fit_rpbnb_tmb.R:41-49`, `R/fit_rpbnb_tmb.R:362-382`, `R/fit_rpbnb_tmb.R:387-395`, `R/fit_rpbnb_tmb.R:441-445`; `comments/response_2026-08-08-07-36-52.md:73-76`.

The response says the finite-draw bound is the correct notion for SML because the simulated objective evaluates only those Halton nodes. That confuses a numerical integration rule with the support of the model being approximated. The fitter's own documentation says SML and Laplace are “different approximations to the same [random-coefficient] integral.” Normal and lognormal coefficients retain their continuous distributions; they are not redefined as a discrete distribution supported only on the selected Halton points.

With a Normal random coefficient and a nonzero loading in both margins, the latent support still lets `c1` and `c2` approach every corner of `(0,1)^2`, so the support-valid Famoye interval is `[-1,1]` regardless of whether that integral is approximated by Laplace or Halton quadrature. A finite SML grid can instead return the wider intervals already reproduced in the response and admit `lambda = 2`. The unsampled latent-tail neighborhoods where the conditional PMF is negative have positive probability under the stated Normal mixing distribution. More draws may make the numerical approximation denser, but they must not change which parameter values define a valid probability model.

Use latent-support bounds for SML as well as Laplace. Normal coefficients give the full unbounded-support result; lognormal can use its one-sided attainable range; Uniform and triangular coefficients need their bounded coefficient-support ranges propagated to per-observation `c` intervals. The alternative would be to redefine and document SML as fitting a draw-dependent discrete mixing distribution, but that would contradict the current API, simulator, and “same integral” contract.

### P1 - R underflow can make the Laplace bounds helper drop a random effect that TMB keeps positive

**Locations:** `R/fit_rpbnb_tmb.R:411-430`, `R/utilities.R:91-109`; compare `src/rpbnb_tmb.cpp:695-724`.

`.lambda_bounds_latent()` computes `s <- exp(log_scale)` in R and declares an observation varying only when `s > 0`. Any finite start is accepted, so a user can supply `log_sd = -1000`; R evaluates `exp(-1000)` as zero and the helper treats that margin as fixed. The TMB likelihood does something different: it clamps `log_sd` to `-20` before exponentiation, leaving a strictly positive scale. With a Normal latent and nonzero loading, an arbitrarily small positive scale still has unbounded support and requires the varying-margin bound.

For the simple `mu1 = mu2 = 1`, `m1 = m2 = 0.5` case, this mismatch makes the helper use `[-2.999874779, 4.098107520]` while the two-varying-margin support requires `[-1,1]`. Thus a value such as `lambda = 2` can again enter the Laplace objective and later be reported admissible. The new tests use ordinary scales and do not exercise this template/R boundary mismatch.

Determine variation from the declared random coefficient and nonzero design loading, not from the floating-point result of `exp(log_scale)`. The fixed-margin `m` and mean calculations should likewise use transformations matching the template clamps so the R-side constraint and TMB objective share one parameterization at all accepted starts.
