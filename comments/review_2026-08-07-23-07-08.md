# rpbnb project review

**Reviewed:** 2026-08-07 23:07:08 America/New_York  
**Target:** `merge-tmb-engine` at `7627fb1`, compared with `master` at `a27cc77`  
**Scope:** the merged Rcpp and TMB engines, especially the new TMB likelihood, inference and post-estimation API, simulations, tests, package metadata, and release hygiene. The working tree was clean when review began.

## Executive assessment

The merge adds a substantial and unusually well-explained TMB implementation. The code contains careful work on tail probabilities, native registration, RNG preservation, memory budgeting, input alignment, and independent numerical references. The test suite is broad, and comments often document not just what an approximation does but the failure that motivated it.

The branch is not ready to merge as a generally usable engine. Two known conditions can currently violate basic safety or model validity: a supported public argument can segfault the R process, and the TMB Famoye parameterization can leave the admissible PMF region as the mean and dispersion parameters move away from their starting values. The Gaussian likelihood also knowingly replaces many representable tail cells with the `1e-300` floor. Test infrastructure then masks some clean-checkout errors, so a green tier run is not reliable evidence until the runner is fixed.

## Prioritized findings

### P0 - A public Gaussian/OpenMP configuration is known to segfault R but is not blocked

**Locations:** `R/fit_rpbnb_tmb.R:253`, `R/fit_rpbnb_tmb.R:376`, `tests/testthat/test-parallel.R:498-560`, `README.md:146-152`.

The repository records that constructing a Gaussian-copula TMB object with two threads and evaluating it causes a native `SIGSEGV`. The test deliberately skips the parallel Gaussian call because it terminates the whole R process. Despite that, `fit_rpbnb_tmb()` passes `control$n_cores` through for every family without checking `family_code == 2L`. Therefore this valid-looking public call can crash the user's session on an OpenMP-capable build:

```r
fit_rpbnb_tmb(...,
  dependence = copula("normal"),
  control = rpbnb_tmb_control(n_cores = 2L))
```

A README warning is not a sufficient guard against memory corruption/process termination. Until the registered Gaussian atomic is thread-safe, force the realized thread count to one for this family (with a warning) or reject `n_cores > 1` before `MakeADFun()`. Add a subprocess regression that asserts a controlled error rather than attempting the crashing call in the main test process.

### P0 - Frozen TMB Famoye bounds can admit a negative joint PMF after parameters move

**Locations:** `R/fit_rpbnb_tmb.R:311-335`, `src/rpbnb_tmb.cpp:735`, `src/rpbnb_tmb.cpp:893-912`.

The TMB fitter computes the global lambda interval once from the starting means, dispersions, and draws, then treats `lamLo` and `lamHi` as fixed data for the entire optimization. The C++ template acknowledges the consequence: when the current parameters leave that interval's valid region, it penalizes only an observed dependence factor that is non-positive. This does not enforce non-negativity over the count distribution's full support.

A direct counterexample using the package's corrected `lambda_bounds_vec()` is:

```text
start:   mu1 = mu2 = 1,   m1 = m2 = 0.5
         frozen bounds = [-2.999875, 4.098108]

current: mu1 = mu2 = 0.1, m1 = m2 = 0.5
         valid bounds  = [-1.132545, 17.637867]

lambda = -2 is admitted by the frozen box.
For an observed (0, 0) cell, the dependence factor is 0.992719 (no penalty).
In the upper-tail limit, the factor is 1 + lambda*c1*c2 = -0.765934.
```

Thus the objective can remain finite at observed low counts while the fitted joint PMF is negative at unobserved high counts. The `1e10` step penalty is also flat on each side, so it supplies no gradient that can steer the optimizer back.

The dependence map must use bounds valid at the current parameter vector and across every current random draw, or use a parameterization/constraint that guarantees the Sarmanov factor over the full support. At minimum, reject a final fit whose lambda is outside recomputed optimum bounds; that would catch invalid results but would not repair the optimized objective.

### P1 - Gaussian tail intervals collapse at the quantile clamp and become constant floor contributions

**Locations:** `src/rpbnb_tmb.cpp:511-523`, `src/rpbnb_tmb.cpp:963-981`, `tests/testthat/test-fit-copula.R:277-315`.

The Gaussian path converts marginal CDF endpoints through `safe_qnorm()`, clamping each probability to `[1e-15, 1 - 1e-15]`. Once both endpoints of a discrete margin exceed the upper clamp, they map to the same normal quantile, the integration interval has zero width, and the cell probability is replaced with `1e-300`. The final floor is flat, so the affected observation contributes no useful likelihood gradient.

On the repository's own 3,487-row `export_dense_all.csv` fixture at its documented starting point (`mu = 1`, `m = 0.5`), 245 `ALL_3` intervals collapse after this clamp. Those cells alone add roughly

```text
245 * -log(1e-300) = 169,240 nats
```

to the negative log-likelihood, even though the NB masses remain representable. The current test explicitly accepts this loss and only checks that the new integral is less wrong than the previous four-corner subtraction.

Carry enough tail information from `nb2_cdf_pair()` to construct distinct normal cut points (for example through survival/log-survival calculations), or evaluate the Gaussian rectangle in a representation that consumes marginal masses directly. Add a reference comparison for the currently collapsed cells and assert that representable masses do not hit the probability floor.

### P1 - The test-tier runner can exit successfully when tests error, and key tests depend on ignored local data

**Locations:** `tools/test-tiers.R:23-73`, `tests/testthat/test-fit-copula.R:187-197`, `tests/testthat/test-fit-copula.R:277-295`, `tests/testthat/test-fit-copula.R:412-433`, `.gitignore:40`, `.Rbuildignore:42`, `NEWS.md:74`.

`as.data.frame(testthat_results)` reports expectation failures in `failed` and test errors separately in logical column `error`. The runner sums only `df$failed` and bases its exit status only on that sum. Its own `CI-friendly` contract is therefore false: an error can be omitted from the printed totals and still produce exit status zero. Testthat's own `all_passed()` checks both conditions (`sum(failed) == 0 && !any(error)`).

This combines with a clean-checkout reproducibility defect. Three tests call

```r
system.file("extdata", "export_dense_all.csv",
            package = "rpbnb", mustWork = TRUE)
```

but that 9.96 MB file is explicitly gitignored and build-ignored. It exists in the current developer checkout but not in the commit or source package. `tools/test-tiers.R` sets `NOT_CRAN=true`, so those `skip_on_cran()` guards do not skip in a normal tier run; a clean checkout errors at `mustWork=TRUE`, and the runner can report success because it ignores `df$error`.

Track a reduced, redistributable tail fixture or synthesize the needed cells in the test. Change the tier accumulator to count/report `error` and fail on either failures or errors; preferably call testthat's supported pass/fail predicate rather than duplicating its semantics. Reference: [testthat result summarization and `all_passed()`](https://github.com/r-lib/testthat/blob/main/R/reporter-list.R).

### P1 - TMB summaries reintroduce invalid significance tests for random-effect scales

**Locations:** `R/tmb_methods.R:103-128`; compare the resolved Rcpp behavior documented in `NEWS.md` under "Review fixes (2026-07-15 model review)".

For each `log_sd*`, `log_s*`, or `log_w*` parameter, `summary.rpbnb_tmb_fit()` reports `exp(log_scale)` as the natural-scale estimate, but computes a p-value from `log_scale / SE(log_scale)` and labels it with significance stars under "Random-coefficient SDs." This tests `log_scale = 0`, i.e. natural scale `= 1`; it is not a test that the random-effect scale is zero. Zero is a boundary corresponding to `log_scale = -Inf`, where ordinary two-sided Wald inference is not valid.

The displayed `Std. Error` is also the log-scale SE beside the natural-scale estimate, not the delta-method natural-scale SE, which makes the row internally ambiguous.

Remove the p-values and stars from positive scale rows unless an explicit hypothesis is stated. Clearly label log-scale estimates/SEs, or report natural scale with `SE(scale) = scale * SE(log_scale)`. Use a boundary-aware LR/score/bootstrap procedure for a zero-variance test. This is the same issue already fixed for the Rcpp engine and should not be reintroduced by the second engine.

### P2 - `rpbnb_tmb_control()` accepts invalid fields; a negative Halton burn silently changes the draw count

**Locations:** `R/tmb_utilities.R:395-447`, `R/tmb_halton.R:22-45`.

The constructor validates `n_cores`, `max_threads`, `max_workload`, `parallel_tape`, `gradtol`, and `restarts`, but coerces `iterlim`, `reltol`, `print_level`, and `halton_burn` without validating type, length, finiteness, or range. Confirmed accepted objects include `reltol = -1`, `print_level = NA`, and `halton_burn = -1`.

The last case silently violates the draw contract:

```text
.tmb_halton_uniform(n_draws = 10, d = 1, burn = -1)
requested rows = 10; returned rows = 9
```

Validate every control field in the constructor: positive whole `iterlim`, positive finite `reltol`, non-negative whole `print_level` and `halton_burn`, plus upper bounds before integer coercion. The public fitter should also verify that `control` inherits from `rpbnb_tmb_control`, because direct calls bypass the wrapper's engine-type check.

## What is working well

- The merge preserves one registered DLL for both Rcpp and TMB and includes a focused registration drift test.
- Formula preprocessing is shared, keeps the two response rows aligned, and explicitly rejects TMB offsets rather than silently discarding them.
- `fit_rpbnb_tmb()` preserves the caller's RNG stream while still making randomized Halton draws reproducible.
- The copula work contains unusually strong numerical commentary and several independent checks: exact well-conditioned references, tail asymptotics, strong-dependence limits, gradient comparisons, and serial/parallel comparisons where safe.
- The fitted object offers deliberate memory levels (`keep`) and inference levels, and exposes optimizer gradients, boundary diagnostics, realized threads, and frozen lambda bounds instead of hiding them.
- Prediction and marginal-effect code retains distribution metadata and integrates over the actual saved draws for all supported random-coefficient distributions.

## Recommended remediation order

1. Prevent Gaussian TMB fits from realizing more than one thread until the native crash is fixed.
2. Replace the frozen-start Famoye constraint with a full-support-valid current-parameter constraint; reject existing invalid endpoints in the meantime.
3. Remove the Gaussian CDF clamp as a load-bearing likelihood approximation and add accurate tail-cell references.
4. Make the test runner fail on `error` and make every tier reproducible from tracked files.
5. Remove invalid random-scale significance tests and clarify estimate/SE scales.
6. Complete control validation, then clean the installed research scripts and stale documentation.

## Bottom line

The merged engine demonstrates serious numerical engineering, but the current public surface overstates its safety: one accepted setting can crash the process, and two dependence paths can evaluate something other than a valid or accurate joint PMF in documented regimes. Fix those three items and the false-green test runner before merging. The remaining inference and maintenance findings are straightforward hardening work after the likelihood is trustworthy.
