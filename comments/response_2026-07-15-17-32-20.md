## P0 — Sarmanov lower λ bound does not guarantee a non-negative PMF

**Confirmed.** Independently re-derived the admissible region and it matches the reviewer exactly.

With `h_t(y) = exp(-y) − c_t` and `c_t = (1 + (1−e⁻¹)·m·μ)^(−1/m) ∈ (0,1)`, the mixing function ranges over `(−c_t, 1−c_t]`. For `1 + λ·h₁h₂ ≥ 0` across the full support, the binding corners are:

- `λ_min = −1 / max((1−c₁)(1−c₂), c₁c₂)`
- `λ_max = +1 / max((1−c₁)c₂, (1−c₂)c₁)`

The code (`R/famoye_core.R:24-28`) computes the *upper* bound with `pmax(c1*(1-c2), c2*(1-c1))` — i.e. it already takes the max over both corners — but computes the *lower* bound as `-1 / ((1 - c1) * (1 - c2))`, omitting the `c₁c₂` corner. `src/halton_parallel.cpp:162-164` duplicates the identical formula. So this is not "R disagrees with C++"; both agree with each other and are wrong in the same direction. The asymmetry (upper uses `max`, lower does not) confirms this is an oversight, not a modeling choice.

When `c₁c₂ > (1−c₁)(1−c₂)` — the low-mean / large-`c` regime — the implemented bound is strictly more negative than the feasibility limit, admitting λ that drives the joint PMF negative. The `pmax(dep, 1e-300)` floor in the likelihood and the `pmax(P2*W, 0)` + row renormalization in `simulate_bnb.R:102-104` suppress the symptom numerically but silently change the sampled/estimated model.

**Plan.** Change the lower bound to `-1 / max((1-c1)*(1-c2), c1*c2)` in `R/famoye_core.R` and mirror it in `src/halton_parallel.cpp` (and confirm `copula_parallel.cpp` is unaffected — it does not use this bound). Add tests that assert full-support non-negativity of the joint PMF on a large count grid at both λ endpoints, including a `c > 0.5` case such as `μ₁=μ₂=0.1, m₁=m₂=0.5`. Because the bound is shared by fixed BNB, RP-BNB, the Hessians, and the simulator, I will treat all existing negative-λ estimates and simulations as unvalidated and re-run the affected recovery/benchmark studies after the fix. Positive-λ fits should be re-checked but are not expected to move (the upper bound was already correct).

**Note:** this is the one change with model-validity consequences and downstream re-validation work. I recommend doing it first and in isolation.

## P1a — RP prediction and natural-scale reporting ignore non-normal random distributions

**Confirmed.** `.bnb_predict_mu()` (`R/methods.R:20-41`) greps a single `sd_prefix`, and both callers hard-code `"log_sd1"`/`"log_sd2"` (`methods.R:47-48`, `308-309`). It applies the normal-only correction `0.5 * sd² * x²` (`methods.R:37`). Per `R/rand_dist.R`, uniform/triangular scales live under `log_w` and lognormal under `log_s`; neither is matched, so for those fits `predict()` silently reverts to `exp(x'β)` with no random-coefficient correction. The natural-scale summary (`methods.R:108-112`) collects only `^log_sd[12]:` rows, so `log_w`/`log_s` scale rows are absent from the printed table. The fit object (`R/fit_rpbnb.R:387-396`; copula constructor call `fit_rpbnb_copula.R:122-132`) stores no `dist`/`sign` fields even though they are computed and used during the fit, so correct behavior cannot be reconstructed later.

**Plan.** Persist the normalized random spec (`dist1/dist2/sign1/sign2/scale`) and the prediction draw settings/seed on the fit object. Implement distribution-aware prediction: analytic mean where a closed form exists (normal), controlled simulation otherwise, and explicit handling of the lognormal case where the population `E[exp(xβ)]` can be `+∞` even when a finite draw set averages to something finite — that estimand must be labeled, not silently reported. Extend the natural-scale summary to emit `log_w`/`log_s` rows. Add prediction/summary tests for every supported distribution on both Famoye and copula fits.

## P1b — Natural-scale Wald p-values for dispersion and random scales are not tests of zero

**Confirmed, with the algebra checked.** For a positive parameter `a = exp(η)`, the summary reports `est = exp(η)` and delta-method `SE = exp(η)·SE(η)`, so `z = est/SE = 1/SE(η)` (`R/methods.R:91`, driven by rows at `110-111` for `log_sd` and `115-122` for `log_m`). This ratio is independent of the point estimate and is not a Wald test of `a = 0`; `a = 0` is `η = −∞`, a boundary outside the delta-method's interior parameterization. Significance stars are nonetheless attached (`methods.R:96,105`). The log-scale table is not a zero-variance test either: testing `log_sd = 0` tests `sd = 1`.

The dependence-parameter rows (λ via `plogis`, copula θ/τ via `z_to_native`) use different transforms and are not implicated by this identity — the issue is specific to the `exp()`-transformed `log_sd`/`log_m` rows.

**Plan.** Remove p-values and significance stars for the positive scale/dispersion components (`sd`, `m`) on the natural scale. Report estimate and CI only. Where a genuine test of a variance/dispersion component is wanted, provide a boundary-aware option (LR mixture, score, or bootstrap) rather than a naive Wald. Keep regular zero tests where zero is interior (λ, Gaussian ρ, Frank θ); flag Clayton independence as a boundary case.

## P1c — Simulator and dependence inputs are insufficiently validated

**Confirmed, all five sub-claims.**

- `copula()` (`R/copula.R:23-26`) runs only `match.arg(family)` — no `par` domain check — so `copula("normal", par=1.2)` is accepted and `sqrt(1 - rho^2)` yields `NaN → NA` counts in the sampler (`simulate_rpbnb_copula.R:12`).
- `copula("kimeldorf", par=-1)` is accepted; `theta < 1e-8` sends the sampler down the independence early-return (`simulate_rpbnb_copula.R:24-28`) while `log(copula$par) = log(-1) = NaN` corrupts the recorded Kendall τ (`74-75`).
- A character random spec with no scale (`random_1 = "x1"`) parses to `scale = NA` (`rand_dist.R:76-80`) and flows unchecked to `NA` `mu1`/`y1`; the copula simulator has no follow-up scale/name guard.
- `simulate_rpbnb_copula()` omits the dispersion-names, random-name, and non-missing-scale checks that `simulate_rpbnb()` performs via `chk_rand` (`simulate_rpbnb.R:35-51`).
- `fit_rpbnb(dependence = "typo")` falls through to the Famoye path because there is no `match.arg(dependence)` (`fit_rpbnb.R:90-97`); only `inherits(..., "rpbnb_copula")` is checked. `fit_bnb()` does validate (`fit_bnb.R:308`).

**Plan.** Validate native copula domains in `copula()` whenever `par` is supplied (`|rho| < 1`; Clayton `theta > 0`; finite Frank θ). Extract the `simulate_rpbnb` validation into a shared helper and call it from `simulate_rpbnb_copula` (reject missing/non-positive scales and dispersions, unknown random names). Make `fit_rpbnb()` accept only `"famoye"` or an `rpbnb_copula` object and error otherwise.

## P2a — Default RP numeric SEs are not the curvature of the optimized simulated likelihood

**Confirmed.** The default `se_method = "numeric"` path calls `set.seed(seed + 1L)` and regenerates a smaller Halton set `Z1_h/Z2_h` (`fit_rpbnb.R:284-293`), then evaluates a frozen-bound Hessian at `par_hat` using those draws (`307-319`) — not the optimization draws `Z1_opt/Z2_opt` generated under `set.seed(seed)`. The default Hessian draw count is `100` (`control.R:42`), where simulation noise can dominate variance-component curvature. The copula numeric path, by contrast, reuses its optimization draws for the Hessian (`fit_rpbnb_copula.R:34-38, 100-101`), which is the coherent behavior.

**Plan.** Make same-draw curvature the default for the Famoye RP numeric path (reuse `Z1_opt/Z2_opt`), matching the copula path and the analytic/OPG options. If a resimulated Hessian is retained as an option, label it explicitly as approximate and expose a draw-count/seed sensitivity check. Do not compare MSL AIC/BIC across materially different draw rules without a simulation-error caveat.
