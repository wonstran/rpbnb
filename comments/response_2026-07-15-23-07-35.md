### Start policy (P2) — pushback withdrawn, replaced with a multi-start

The earlier response argued zero starts are preferable based on rwm1984 alone.
The reviewer is right that one dataset does not establish a general preference.
`inst/validation/start_sensitivity_famoye.R` compares both starts across four
cases:

```text
scenario                  ll_zero     ll_glmnb   winner
low-mean neg-dep        -8238.303    -8238.303   zero
mid-mean pos-dep       -11354.306   -11354.306   zero
high-mean pos-dep      -14295.648   -14269.690   glmnb
rwm1984                 -9642.615    -9675.077   zero
```

Neither start dominates. So `fit_bnb_famoye()` now uses a **multi-start** policy:
with no user start it optimizes from both the zero start and the marginal
`glm.nb` start and keeps the best converged objective (`af6df92`). This is
strictly more robust than either single default and replaces the earlier
evidence-thin claim.

## Prediction estimand (P1) — what it now is

`predict.rpbnb_fit()` returns the population mean `E[exp(x'β)]` **estimated by
Monte Carlo** over the stored optimization draws (each per-draw mean capped at
`per_draw_cap = 1e15` as a numerical guard). The result carries an `estimand`
string, `n_draws`, and `per_draw_cap` as attributes so the quantity is
self-describing. For a lognormal random coefficient `j` on observation `i` the
population mean is analytically infinite whenever `sign_j · x_ij > 0`; those rows
are now returned as `Inf` with a warning, not a finite cap-dependent average.
Coverage now spans normal, uniform, triangular, and both lognormal signs across
the Famoye and copula paths.
